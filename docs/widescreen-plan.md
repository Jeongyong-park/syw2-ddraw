# 전장 16:9 모드 구현 계획

상태: 설계 및 조사 계획. 아직 와이드 모드 구현이나 게임 실행 파일 수정은 하지 않았다.

후속: [1차 분석 및 격리 시제품](widescreen-analysis.md)에서 원본 복사 함수의 4바이트 정렬
제약을 재현했다. 현재 표시 크기 후보는 1068×600, HUD 오프셋은 134로 조정했다.
아래 1067 후보는 조사 시작 당시의 목표이며 엔진 연결과 실제 전장 검증은 남아 있다.

## 목표와 범위

800×600 기준의 유닛·지형·HUD 크기를 유지하면서 전장에 좌우 시야를 추가한다.
메뉴·로비·로그인은 기존 800×600을 유지한다. 디스플레이 설정에
`전장 비율: 기본 4:3 / 와이드 16:9`를 추가하며 기본값은 4:3으로 둔다.
초기 버전은 저장 후 게임 재시작으로 적용한다. SYW2X 해상도 확장에 의존하지 않는다.

| 요소 | 목표 |
|---|---|
| 전장 내부 크기 | 1067×600을 우선 후보로 조사 |
| HUD | 기존 800픽셀 너비, 하단 중앙 |
| 상단 자원 표시 | 중앙 800픽셀 영역을 기준으로 이동 |
| 추가 시야 | 좌우 약 133픽셀, 실제 지형·유닛 렌더링 |
| 미니맵 | 기존 크기와 중앙 HUD 내 위치 유지, 카메라 영역 표시 갱신 |
| 화면 끝 스크롤 | 넓어진 전장 바깥쪽 경계를 기준으로 동작 |
| 저장 파일 | 기존 형식 유지, 화면 설정은 HQCDD 설정에 저장 |

600×16/9는 1066.666…이다. 1067은 확정된 엔진 지원 해상도가 아니다.
버퍼 pitch, 타일 단위와 클리핑 제약을 먼저 확인하고 필요하면 1068 등으로 조정한다.
픽셀 좌표에서 HUD 중앙 오프셋은 정수로 고정하고 1픽셀 비대칭을 허용한다.
출력 비율의 미세한 오차는 별도로 결정하며, 이미지 가로 크기와 메모리 pitch를 혼동하지 않는다.

## 현재 구조와 필요한 분리

`src/ddraw.cpp`의 `Draw::present`는 primary surface에 이미 합성된 게임 화면을
GPU 또는 GDI로 출력한다. `src/viewport.h`는 화면·컨트롤·입력에 공통 비율 변환을 적용한다.
출력만 확대해도 엔진이 그리지 않은 좌우 지형이 생기지는 않는다.

엔진 내부에서 전장 버퍼와 카메라 렌더링 범위를 확장하고 HUD의 그리기 및 클릭 영역을
중앙으로 이동시키는 방식을 우선 조사한다. 화면 출력 단계에서 HUD를 잘라 재배치하는 방식은
HUD 뒤쪽 전장 정보가 소실되므로 기본 설계로 채택하지 않는다.

화면 좌표, 전장/카메라 좌표, HUD 로컬 좌표의 관계를 명시한다. 가능하면 게임 내부의
HUD 원점 변경을 그리기와 입력에 함께 적용해 기존 출력 변환을 유지한다.
엔진에서 지원하지 않는 부분만 입력 영역별 변환을 추가하고 이중 보정을 방지한다.

## 단계별 작업과 완료 조건

### 1. 읽기 전용 분석과 기준 측정

- 현재 ESL EXE와 SYW2X ASI의 해시 및 패치 대상을 기록한다.
- 전장 진입/퇴장, surface 생성, 버퍼 할당, pitch, 카메라 크기, 타일 및 유닛 클리핑,
  HUD 그리기·히트 테스트, 미니맵과 가장자리 스크롤 경로를 추적한다.
- SYW2X `ViewPortPlusOn`의 패치 범위와 실행 순서를 확인한다.
- 같은 37유닛 이상 세이브에서 800×600 기준 화면·입력·성능을 기록한다.

완료 조건: 수정 지점과 원래 바이트, 좌표 관계, 버퍼 크기의 근거를 문서로 남긴다.
아직 확인하지 않은 주소나 상수를 구현에 넣지 않는다.

### 2. 좌우 전장 확장 시제품

- 별도 테스트 사본에서 전장 버퍼·화면 생성·렌더링 및 클리핑 범위를 함께 확장한다.
- 1067×600 후보를 시험하고, 정렬 제약이 있으면 근거를 기록한 뒤 너비를 조정한다.
- 중앙 카메라 위치와 세로 시야, 유닛의 크기는 기준 화면과 같게 유지한다.
- 새로 보이는 좌우에 실제 지형·유닛이 그려지는지, 맵 가장자리 및 안개가 정상인지 확인한다.

완료 조건: 단순 늘이기·복제 없이 추가 시야를 확보하고 버퍼 경계를 벗어나지 않는다.
이 조건이 확인되기 전에는 설정 UI에 작동 가능한 기능으로 노출하지 않는다.

### 3. HUD와 입력 정합성

- 하단 HUD, 상단 자원 표시, 툴팁·팝업의 기준점을 결정한다.
- HUD 양옆은 가능하면 전장을 표시하고 전장 입력을 허용한다. HUD의 투명하거나 장식된
  경계에서는 기존 히트 테스트를 확인해 클릭이 의도치 않게 관통하지 않도록 한다.
- 좌우 추가 영역의 유닛 선택·명령, HUD 버튼, 생산 단축키, 드래그 선택,
  미니맵 클릭·카메라 사각형, 가장자리 스크롤을 함께 수정하고 검증한다.
- 메뉴·전장 전환과 저장/불러오기에서 기준점이 중복 적용되지 않게 한다.

완료 조건: 보이는 위치와 실제 입력 위치가 일치하고 게임 속도·시뮬레이션에는 변경이 없다.

### 4. 옵션과 SYW2X 공존

- HQCDD에 와이드 모드와 대상 빌드별 패치 정보를 별도 모듈로 둔다.
- 지원 EXE와 원래 명령 바이트를 모두 확인하고 필요한 변경이 전부 가능한 경우에만 적용한다.
  불일치 시 와이드 모드를 적용하지 않고 이유를 로그와 설정 화면에 표시한다.
- SYW2X 확장 ON을 감지하면 중복 적용을 막는다. 초기 구현에서는 사용자가
  SYW2X 확장을 끄고 재시작하도록 안내한다. 다른 SYW2X 기능은 유지한다.
- SYW2X 확장만 안전하게 억제할 수 있다는 근거가 확보되기 전에는 플러그인 전체를
  차단하거나 원본 INI·EXE를 자동으로 덮어쓰지 않는다.

완료 조건: 지원 조건·재시작 안내·실제 적용 상태가 일치하고, 미지원 및 충돌 상태에서
부분 패치가 남지 않는다.

### 5. 회귀·성능 검증과 배포 준비

- 좌표 변환 및 패치 검증은 네이티브 테스트와 기존 Unicorn 인프라로 검사한다.
  Unicorn만으로 실제 렌더링·전체 게임 성능이 검증됐다고 판단하지 않는다.
- 37유닛 이상 전장 세이브에서 이동·전투·생산·드래그·미니맵·화면 스크롤·맵 가장자리를 시험한다.
- 창/전체화면, GPU/GDI, OSD·설정 표시, Alt+Tab, 전장 재진입을 확인한다.
- 동일 세이브와 카메라, VSync 및 출력 조건에서 4:3/16:9를 반복 비교한다.
  출력 FPS, 프레임 간격 p95/p99, 출력 CPU 시간, 입력 lock 대기 및 기존 지연 지표를 기록한다.
  출력 호출 FPS와 게임 애니메이션 진행을 구분하고, 새로 측정하지 않은 광자 지연을 주장하지 않는다.
- 전장 픽셀 수는 약 33% 늘지만 실제 처리 비용은 측정으로 판단한다.
- 기존 네이티브·Python·CI 테스트와 패키징 검증을 수행하고 문서를 갱신한다.

실제 게임 속도나 클릭 실패의 재현 가능한 회귀가 있으면 기본 기능으로 배포하지 않는다.
OS별 수동 검증은 기존 합의대로 1.0 이후로 미룬다. 온라인 호환성은 별도 검증 대상으로
남기며 싱글 전장 검증 결과를 온라인 전체 호환성으로 확대하지 않는다.

## 첫 구현 작업

첫 작업의 범위는 1단계 분석과 2단계 시제품이다. 전장 확장 가능 여부 및 정확한 내부 너비를
확정한 뒤 HUD·입력·설정 UI를 연결한다. 이 문서 작성은 구현 완료나 지원 확정을 의미하지 않는다.
