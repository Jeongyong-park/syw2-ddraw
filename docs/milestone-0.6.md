# 0.6 배포 기반 구현·검증 계획

대상: [마일스톤 0.6](https://github.com/Jeongyong-park/syw2-ddraw/milestone/1),
[문서·버전 #1](https://github.com/Jeongyong-park/syw2-ddraw/issues/1),
[설치·복구 #2](https://github.com/Jeongyong-park/syw2-ddraw/issues/2).

## 구현 범위

1. 최종 사용자는 ZIP 루트의 ddraw.dll과 hqcdd.ini만 게임 EXE 옆에 복사한다.
2. 사용자 ZIP과 개발용 소스 ZIP을 구분한다. INSTALL.txt, README, 라이선스와 실제 화면을 제공한다.
3. VERSION과 DLL 메타데이터를 확인하고 ZIP별 SHA-256 파일을 생성한다.
4. 원본 게임 없이 일반 DDRAW.dll import 경로를 검증하는 x86 테스트 프로그램을 만든다.
5. 실제 사용자 ZIP을 한글·공백 임시 경로에 풀어 DLL 로드·DirectDraw7·클리퍼를 검사한다.
6. CI에서 두 ZIP과 해시를 다운로드 가능한 산출물로 제공한다.

자동 설치기는 만들지 않는다. 사용자가 백업·복사하는 설치에서 파일 덮어쓰기를 도구가 막는다고 주장하지 않는다.
원래 DLL 백업과 INI 보존은 명확한 수동 절차와 실제 환경 시험으로 확인한다.

## 현재 증거와 한계

- 기존 코드: VERSION 기반 빌드·로그·속성, README/CHANGELOG/개발자 문서 및 스크린샷.
- 기존 로컬 시험: 별도 시험본 게임 화면과 ddraw.dll로 이름을 바꾼 통합 테스트.
- Unicorn: 실제 viewport 소스를 컴파일한 x86 코드의 1,008개 좌표·배율 사례 통과. OS API·실제 게임 검증은 제외.
- 이번 자동 검증: 패키지 구성·해시, 실제 추출 DLL의 속성, EXE import 로딩과 시스템 클리퍼.
- 자동 import 테스트는 GPU 출력·실전 전투·Windows 10/11 무개발도구 환경을 증명하지 않는다.
- CI 러너에는 개발 도구가 있으므로 #2의 무개발도구 PC 항목은 통과 처리하지 않는다.

## 수동 검증표 — 결과가 없으면 미검증

Windows 10과 11에서 각각 수행한다. 각 행에 날짜, OS 빌드, GPU/드라이버,
ZIP SHA-256, DLL 버전, 원본 EXE SHA-256, 관찰 결과와 로그 위치를 기록한다.

| 확인 항목 | Windows 10 | Windows 11 |
| --- | --- | --- |
| Visual Studio/Python 없는 PC에서 ZIP만으로 설치 | 미검증 | 미검증 |
| 기존 EXE로 시작·HQNET 로그인·로비·전투·정상 종료 | 미검증 | 미검증 |
| 한글·공백 게임 경로에서 동일 동작 | 미검증 | 미검증 |
| 설치 전후 EXE·게임 데이터 동일 | 미검증 | 미검증 |
| 기존 DLL 백업 및 다른 기존 백업 보존 | 미검증 | 미검증 |
| 새 HQCDD DLL 업데이트 후 INI 설정 유지 | 미검증 | 미검증 |
| 원래 DLL 복원 후 이전 실행 환경 복귀 | 미검증 | 미검증 |
| 원래 로컬 DLL이 없던 설치에서 제거·재실행 | 미검증 | 미검증 |

실제 설치 시험은 별도 게임 사본이나 사용자가 승인한 시험 환경에서 수행한다.
실행 중인 게임이나 기존 설치의 DLL을 무단으로 교체하지 않는다.

## 완료 판단

#1의 구현 증거와 #2의 실제 설치 재현 결과를 각각 기록한다.
두 OS의 필수 수동 검증이 남아 있으면 0.6 마일스톤을 닫지 않는다.
호환성·장시간 전투·진행 속도 조사는 후속 마일스톤과 연결하되 빌드 성공으로 대체하지 않는다.
