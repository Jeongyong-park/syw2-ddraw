# 실험적 와이드 전장

현재 개발 소스는 ASI 방식의 전장 16:9 모드를 지원합니다. 기존 v0.6.2 배포물에
포함됐다는 의미는 아닙니다. 기본값은 4:3입니다.

Ctrl+Alt+D에서 전장 비율을 선택하고 저장한 뒤 게임을 재실행합니다.
16:9는 전장 내부를 1068×600으로 확장하고 기존 800픽셀 HUD를 X=134에 배치합니다.
메뉴·로그인·로비는 기존 모드를 사용합니다. 디스크의 게임 EXE는 수정하지 않습니다.

## 지원 조건

- ASI 빌드와 검증된 ESL 2606 원본이 필요합니다. SHA-256은
  `716dde6a1cd837c74c83c426fba634491143d624c0c284aad4dc4d5d5ea2417f`입니다.
- 원본 파일 해시와 모든 패치 위치가 일치해야 적용합니다.
- SYW2X의 `ViewPortPlusOn=1`이면 16:9 적용을 중단합니다. 지원 이미지에서는
  비율 선택을 유지하므로 UI에서 4:3을 저장해 요청을 해제할 수 있습니다.
- 저장된 선택과 실제 실행 비율은 다를 수 있습니다. 비율 선택을 바꾸지 않았다면
  다른 화면 설정은 저장하지 않고도 현재 실행에 적용할 수 있습니다.

## 검증 범위

원본 ASI로 전장 실행, 중앙 HUD와 풍향계 배치를 확인했습니다. 피격 경고는
좌표·타이밍 에뮬레이션과 실행 중 패치 적용을 확인했지만 최종 표시 위치의
유효한 캡처 확인은 남아 있습니다.

시야 갱신과 송신 메시지의 제한된 비교는 통과했습니다. 실제 두 클라이언트의
4:3/16:9 혼합 멀티플레이와 같은 틱의 시뮬레이션 상태 비교는 미검증입니다.
전체 높이 캐시 갱신으로 중앙 카메라의 타일 순회가 4배로 늘었습니다.
37창병 전장의 비율별 성능 A/B는 아직 수행하지 않았습니다.

## 구현과 실험 파일

| 경로 | 역할 |
| --- | --- |
| `src/widescreen_runtime.*` | 원본 검증, 동적 메모리 할당, 재배치와 패치 적용 |
| `src/widescreen_recipe.h` | 생성된 167개 패치와 중계 코드. 직접 편집하지 않음 |
| `src/battle_aspect.h` | 비율 초기화와 과거 시제품 EXE의 복원 표 호환 |
| `tools/widescreen/export_widescreen_patch.py` | 검증된 원본·시제품으로 패치 명세 생성 |
| `tools/widescreen/` | 선택적 로컬 분석·에뮬레이션 구현 |
| `tests/support/wide_terrain_model.h` | 초기 512줄 CPU 캐시 모델. 운영 캐시가 아님 |
| `tests/widescreen_test.cpp` | 위 초기 모델의 복사·스크롤 검사 |
| `tests/widescreen_runtime_test.cpp` | 운영 패치 경로의 검증·재배치·충돌 검사 |

운영 캐시는 1088×608이며 600줄을 복사합니다. 초기 512줄 모델 테스트의 통과를
운영 렌더링 검증으로 취급하지 않습니다. 분석 도구는 게임 파일과 pefile/Unicorn 등
별도 의존성이 필요하며 사용자 설치에는 필요하지 않습니다.

기존 `tools/export_widescreen_patch.py`, `tools/verify_widescreen_*.py` 등의 경로는
호환 진입점으로 유지합니다. 새 경로는 저장소 루트에서
`python -m tools.widescreen.export_widescreen_patch ...` 형태로 실행합니다.

변경 근거와 개별 실험 결과는 [분석 기록](widescreen-analysis.md)에 보존합니다.
