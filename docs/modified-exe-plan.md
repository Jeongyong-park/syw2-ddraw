# 수정 EXE의 16:9 호환성 검사

## 범위

외부 프로파일 없이 ASI 안에 기준 구조와 영역별 SHA-256을 포함한다. 1단계는
주소가 유지되고 `.text`, `.rdata`, 초기 `.data`가 동일한 실행파일을 지원한다.
아이콘·버전·문자열 리소스, PE 타임스탬프·체크섬 변경을 허용한다.
게임 코드/데이터 변경, 패킹, 새 실행 섹션, 주소 이동의 자동 해석은 범위 밖이다.
일부 패치 바이트만 같다는 이유로 알 수 없는 코드를 실행하지 않는다.

## 구현 순서

1. 기존 생성기에 파일 검증용 내장 명세를 추가한다. 사용자 배포에 새 설정 파일은 없다.
2. 파일 구조와 비리소스 영역을 검사하고 메모리의 원래 패치 바이트를 모두 검증한 뒤 적용한다.
   파일 검증과 메모리 충돌을 구분하며 모든 검증 실패는 쓰기/할당 전에 중단한다.
3. 16:9 요청 실패를 기존 디스플레이 오버레이에서 한 번 안내한다. 확인/Esc로 닫으면
   기존 입력 복원 경로를 사용한다. 설정 화면에도 이유를 남기고 상세 진단은 hqcdd.log에 기록한다.
4. 합성 PE의 리소스 변경/코드 변조/잘못된 구조/범위 오류와 메모리 충돌을 회귀 검사한다.
   확보한 ESL 사본에 리소스만 변경한 경우와 코드가 변경된 경우도 별도로 검사한다.

## 한계

이 검사는 특정 빌드의 구조 호환성 검사이며 임의 수정 EXE의 안전성이나 멀티플레이
호환성을 보증하지 않는다. 다른 ASI가 검사 후 같은 메모리를 덮어쓰는 경우도 자동 조정하지 않는다.
주소 이동 지원은 명령어·참조 관계 분석을 갖춘 별도 후속 단계로 둔다.

## 구현·검증 결과 (2026-09-12)

- 내장 명세와 영역별 검증, 메모리 패치 충돌 분류, 기존 오버레이 안내 구현.
- 네이티브 검사에 합성 PE 호환성 검사와 확인/Esc 알림 종료·입력 복귀 검사를 추가.
- 실제 ESL 사본의 버전 리소스·타임스탬프 수정은 허용하고 코드/데이터 수정은 거부하는 것을 확인.
  로컬 증거는 `output/modified-exe-check/report.json`에 보관한다(배포하지 않음).
- 수정된 EXE의 검사 및 사설 메모리 적용과 실제 게임 플레이는 구분한다.
  이 작업에서 임의의 외부 수정판으로 장시간 전투/멀티플레이를 검증한 것은 아니다.
